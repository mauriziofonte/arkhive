# ArkHive 2.0: restic backend, guided restore, release automation, self-update (specification)

Status: approved design, not implemented. Target release: `v2.0.0` (breaking configuration).

Goal: a serious, dependable backup product. Every behaviour in this document is covered by tests (§13); a feature without tests is not done.

## 1. Why

ArkHive 1.x builds `tar | gzip|xz | openssl enc -aes-256-cbc -salt -pbkdf2` and streams it over SSH. The random salt and CBC chaining make two consecutive daily archives share no common chunk, so every run uploads the full data set and no deduplicating backend can help. Measured on a real host: ~21 GB uploaded every day for a few hundred MB of real change.

ArkHive 2.0 keeps what it is good at (configuration, database dumps, exclusions, locking, notifications, an interactive restore) and delegates transport, deduplication, compression, encryption and retention to [restic](https://restic.net). restic must receive **plain input** (file trees and uncompressed SQL dumps): compressing or encrypting before restic destroys deduplication.

Reference backend: any restic repository; the primary target is an SFTP repository on a Hetzner Storage Box (SFTP on port 23, one sub-account and one repository per source host, server-side read-only snapshots as ransomware protection).

## 2. Keep from 1.x

- `.env`-style config format and discovery list, plus a new `--config <path>` option that bypasses discovery. Fix the discovery base: today `./` resolves to the directory of the executable (`dirname(realpath(argv[0]))`), not the working directory; 2.0 searches the real working directory (`getcwd()`) and documents the order exactly.
- `flock` per destination (now per `RESTIC_REPOSITORY`): a parallel run fails immediately.
- MySQL/MariaDB and PostgreSQL dumps (reworked, §6.2).
- `EXCLUSION_PATTERNS` syntax (converted to restic patterns, §5).
- SMTP notifications (reworked, §6.3).

## 3. Configuration keys removed in 2.0

These keys are dismissed. A config that still contains any of them fails preflight (exit 2) with a message listing each found key, what replaces it, and a pointer to the README migration section. No silent fallback.

| Removed key | Replacement |
|---|---|
| `SSH_HOST`, `SSH_PORT`, `SSH_USER`, `SSH_BACKUP_HOME` | `RESTIC_REPOSITORY` (+ `RESTIC_SFTP_COMMAND` for port/key) |
| `WITH_CRYPT`, `CRYPT_PASSWORD` | `RESTIC_PASSWORD_FILE` (restic always encrypts). A 1.x password is read only by `decrypt-legacy`, from its own `--password-file` or env `ARKHIVE_CRYPT_PASSWORD`, never from the main config |
| `COMPRESSION_TYPE` | `RESTIC_COMPRESSION` (`auto`/`max`/`off`) |
| `BACKUP_RETENTION_DAYS` | `RESTIC_KEEP_DAILY`, `RESTIC_KEEP_WEEKLY`, `RESTIC_KEEP_MONTHLY` (applied by `maintain`) |
| `BACKUP_DIRECTORY` | `BACKUP_PATHS` (one or more absolute paths). Not accepted as an alias: the migration message tells the user to rename it, so every 2.0 config is explicit |
| `SMTP_SSL` (present in the 1.x example, never read) | `SMTP_ENCRYPTION` |

Binaries no longer required: `tar`, `gzip`, `xz`, `openssl` (only for `decrypt-legacy`), `scp`, `pv`, `mkfifo`, `tee`.

## 4. Configuration (2.0)

| Key | Required | Meaning |
|---|---|---|
| `BACKUP_PATHS` | yes | space-separated absolute paths |
| `RESTIC_REPOSITORY` | yes | e.g. `sftp:user@host:/restic` or a local path |
| `RESTIC_PASSWORD_FILE` | yes | repository password file; refused if group- or world-readable or not owned by the running user |
| `RESTIC_SFTP_COMMAND` | no | passed as `-o sftp.command=...`, e.g. `ssh -i /root/.ssh/key -p 23 user@host -s sftp` |
| `RESTIC_BINARY` | no | default `restic` from `PATH`; minimum 0.14 (repository v2, compression) checked at preflight |
| `RESTIC_HOST` | no | `--host` value (default: system hostname) |
| `RESTIC_KEEP_DAILY` / `_WEEKLY` / `_MONTHLY` | no | default 7 / 4 / 6 |
| `RESTIC_CHECK_SUBSET` | no | default `5%` |
| `RESTIC_COMPRESSION` | no | default `auto` |
| `DUMP_DIRECTORY` | if dumps are enabled | staging for SQL dumps, must not be inside an excluded path; included in the snapshot; emptied after a successful backup |
| `EXCLUSION_PATTERNS` | no | as 1.x |
| `WITH_MYSQL`, `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_DATABASES` (`*` = all except system schemas) | no | §6.2 |
| `WITH_PGSQL`, `PGSQL_HOST`, `PGSQL_PORT` (new, default 5432), `PGSQL_USER`, `PGSQL_PASSWORD` (new, optional), `PGSQL_DATABASES` | no | §6.2 |
| `NOTIFY`, `NOTIFY_ON` (new: `always`/`failure`, default `always`), `SMTP_HOST`, `SMTP_PORT`, `SMTP_ENCRYPTION` (`ssl`/`tls`/`none`), `SMTP_USER`, `SMTP_PASSWORD` (both optional: unauthenticated relays allowed), `SMTP_FROM`, `SMTP_TO` | no | §6.3 |

Typing: only keys known to be boolean (`WITH_MYSQL`, `WITH_PGSQL`, `NOTIFY`) are converted from `true/false/yes/no/1/0`; every other value stays a string (1.x turns a password `yes` into `true`). Unknown keys = warning listing them.

## 5. Exclusion conversion

| 1.x pattern | Meaning in 1.x | restic pattern |
|---|---|---|
| `/logs/*` (leading `/`) | anchored to the backup root | `<each BACKUP_PATH>/logs/*` |
| `*.log` | any file named `*.log` anywhere | `*.log` |
| `node_modules/*` | a `node_modules` directory anywhere | `node_modules` |
| `*/vendor/*` | `vendor` directory anywhere below the root | `vendor` |

Written to a temporary `--exclude-file` (0600, removed after the run). Pure function, unit-tested on every pattern in `.arkhive-config.example`. `FileEnumeratorService` (1.x enumeration) is removed.

## 6. Commands

| Command | Behaviour |
|---|---|
| `backup` | preflight (binaries, restic version, password file, repository reachable via `restic cat config`, disk space for dumps) → dumps → `restic backup --json --tag arkhive --host <h> <paths> <dump dir> --exclude-file <f>` → parse the JSON summary (`snapshot_id`, `data_added`, files new/changed/unmodified, duration) → notify → empty the dump directory. restic exit 3 (snapshot created, some files unreadable) = warning |
| `maintain` | `forget --keep-daily --keep-weekly --keep-monthly --prune`, then `check`, then `check --read-data-subset` → notify |
| `restore` | guided restore, §10 |
| `ls [snapshot] [path]`, `find <pattern>` | browse a snapshot, find which snapshots contain a path (§10.3) |
| `drill` | automated restore test (§10.5) |
| `doctor` | environment and repository diagnosis (§10.6) |
| `status [--json]` | latest snapshot time, age in hours, snapshot count, repository raw size (`restic stats --mode raw-data`) |
| `init` | `restic init`; prints a reminder to keep a second copy of the password off the host |
| `decrypt-legacy <file> [--to <dir>] [--password-file <f>]` | decrypts and extracts a 1.x `.enc.arbk` (`openssl enc -d -aes-256-cbc -salt -pbkdf2 -iter 100000`, password via env, never argv); detects gzip/xz/none |
| `self-update` | §9 (`self-upgrade` kept as a hidden alias printing a deprecation notice) |

Progress and prompts depend on the execution context (§11): `--with-progress` is replaced by automatic progress in interactive mode (restic JSON status lines, no `pv`).

Exit codes (stable, documented, tested): 0 success; 1 failure; 2 configuration or usage error (incl. a required answer missing in non-interactive mode); 3 completed with warnings (incl. notification failure); 4 refused for safety (non-empty target, insufficient space, in-place without confirmation); 10 `self-update --check`: update available.

### 6.1 Process execution

- Every external command goes through one helper that returns exit code, stdout and stderr; stderr is never discarded (1.x `wrap_exec` appends `2>/dev/null`).
- Pipelines run with `set -o pipefail` (1.x loses the `mysqldump` exit code behind `| pv`).
- Secrets never on argv: MySQL via a temporary `--defaults-extra-file` (0600, deleted in `finally`), PostgreSQL via a temporary `PGPASSFILE`, restic via `RESTIC_PASSWORD_FILE`. Tests assert that no secret appears in the process list or logs.

### 6.2 Dumps

- One plain file per database (`<db>.sql`), so each database deduplicates and restores independently.
- MySQL/MariaDB: `--single-transaction --quick --routines --triggers --events --hex-blob`; no `--skip-lock-tables` without a transaction. `*` expands to all databases except `information_schema`, `performance_schema`, `sys`, `mysql` unless listed explicitly.
- PostgreSQL: every database in `PGSQL_DATABASES` (1.x dumps only the first), `--format=plain` (1.x `--format=custom` is compressed and defeats dedup), `--no-owner --no-privileges` kept configurable.
- A dump failure aborts the backup before `restic backup` (no snapshot with partial dumps).

### 6.3 Notifications

- Symfony Mailer DSN built with URL-encoded user and password (1.x breaks on `@`, `:`, `/`).
- A notification failure never turns a successful backup into a failure: it is logged and the exit code becomes 3.
- `criticalError` must work before the config is loaded (1.x calls `$this->config->get()` on null).
- Mail body: host, config file, paths, snapshot id, data added, duration, restic version, ArkHive version.

## 7. Engineering rules

- Runtime: PHP **>= 8.3** (Laravel Zero 13 requires it; decided 2026-10-12, replacing the earlier 8.2 floor). Upgrade Laravel Zero from 8.x (end of life) to the current major and `symfony/mailer` accordingly (7.4 LTS: 8.x requires PHP 8.4); PSR-12, strict types.
- Distribution: **PHAR only**, from GitHub Releases (§8). Drop the "composer global require" and per-project install sections from the README (today the framework sits in `require-dev`, so a composer install is broken anyway).
- `builds/` is **removed from `main`** in 2.0: artifacts live only in Releases. This also makes the 1.x `self-upgrade` (which downloads `builds/arkhive.phar` from `main`) fail safely instead of silently installing a config-incompatible 2.0 on 1.x hosts.
- No real host, credential or hostname in code, tests, fixtures, docs or CI: `example.com` and placeholders only.
- README rewritten for 2.0 with a migration section (removed keys table §3, `decrypt-legacy`, restic install). `CHANGELOG.md` created, Keep a Changelog format.

## 8. Release automation (GitHub Actions)

| Workflow | Trigger | Steps |
|---|---|---|
| `ci.yml` | push, pull request | quality gates (§13.4), PHP 8.3 and 8.4 matrix: PHPUnit, e2e (§13.2), distro matrix (§13.3), PHAR build smoke test |
| `release.yml` | push of a tag `v*.*.*` | tag must equal `config/app.php` version (fail otherwise); full CI; build PHAR with box; `php arkhive.phar --version` must print the tag; `sha256sum arkhive.phar > arkhive.phar.sha256`; build provenance attestation (`actions/attest-build-provenance`) on the PHAR; GitHub Release via `gh release create <tag> arkhive.phar arkhive.phar.sha256 --notes-file <CHANGELOG section>`; tags containing `-` (e.g. `v2.0.0-rc.1`) published as pre-releases |

- Workflow permissions: `contents: write`, `id-token: write`, `attestations: write`; nothing else.
- Tags are created by the maintainer, never by CI or by an agent.
- Stable asset names: `arkhive.phar`, `arkhive.phar.sha256`. README install URL: `https://github.com/mauriziofonte/arkhive/releases/latest/download/arkhive.phar`.

## 9. `self-update`

| Option | Behaviour |
|---|---|
| (none) | update to the latest stable release |
| `--check` | print current and latest version; exit 0 if current, 10 if an update exists; no change |
| `--version=<tag>` | install a specific release (downgrade allowed, with a warning) |
| `--pre` | consider pre-releases |
| `--rollback` | restore the previous binary kept by the last update |
| `--allow-major` | required to cross a major version |

- Source: GitHub REST API `GET /repos/mauriziofonte/arkhive/releases/latest` (or `/releases/tags/<tag>`, `/releases` for `--pre`), `User-Agent: ArkHive/<version>`; optional `GITHUB_TOKEN` env for rate limits; honours `HTTPS_PROXY`. HTTP via PHP (curl extension or streams), no `wget`/`curl` binaries.
- Version comparison: semantic (`version_compare` on the tag without `v`).
- Verification: download `arkhive.phar` and `arkhive.phar.sha256` from the release assets; sha256 must match. If `gh` is installed, additionally run `gh attestation verify <file> --repo mauriziofonte/arkhive` and fail on mismatch; without `gh`, print that provenance was not verified.
- Major-version guard: crossing a major version (1 → 2, 2 → 3) requires `--allow-major` and prints the README migration link (config keys change).
- Install: download into the directory of the running PHAR (same filesystem), same mode as the current file, smoke test `php <tmp> --version` must print the expected version, keep the current binary as `<path>.bak-<old version>`, atomic `rename()` over the running PHAR. Refuse with a clear message if the directory is not writable (no partial state).
- Only for PHAR installations; refuses when running from source.

## 10. Restore experience

The 1.x restore is a liability: an unresolvable destination becomes `/` (`realpath()` returns `false`), the whole archive is downloaded into the temp dir without a space check and left behind on failure, the checksum sidecar is not verified, the date choice hangs without a TTY, and only full restores of the latest days exist. 2.0 rewrites restore around one principle: **a stressed operator restores the right data, to a safe place, without reading the manual.**

### 10.1 Guided restore (interactive)

`arkhive restore` in a terminal runs a wizard; every step shows the default and can be skipped with Enter:

1. **Repository check**: reachable, password valid, lock state; a stale lock gets a one-line explanation and the exact `restic unlock` suggestion (never run automatically).
2. **Snapshot**: table newest first (date, age, host, paths, size, tag); default = latest. Filter by host/path when the repository holds several.
3. **What**: everything / pick files and folders (browse with search, multi-select) / one database dump / a single file to stdout.
4. **Where**: default a new directory `./arkhive-restore-<host>-<snapshot short id>-<YYYYmmdd-HHMMSS>` (never the original location); any existing non-empty target is refused (exit 4) unless explicitly confirmed.
5. **Pre-flight**: estimated restore size (`restic stats <id> --mode restore-size`, per selection) vs free space on the target filesystem (PHP `disk_free_space`); not enough space = refuse with both numbers (exit 4).
6. **Summary and confirmation**: one screen with snapshot, selection, target, size, ownership mode; then restore with progress.
7. **Verification**: `restic restore --verify` (restic >= 0.17; otherwise post-restore hash check of the selection) and a final report: files, bytes, duration, target path, and the next step (e.g. the exact command to move the data into place or to import a dump).

### 10.2 Non-interactive restore (scripts, cron, remote shells)

Every wizard choice has a flag; with no TTY the wizard never starts:

| Flag | Meaning |
|---|---|
| `--snapshot <id\|latest>` | required (no implicit choice without a TTY) |
| `--include <path>` (repeatable), `--exclude <pattern>` | selection; none = everything |
| `--target <dir>` | required; must not exist or be empty |
| `--db <name>` | restore that dump only; with `--import-as <new db>` imports it into a NEW database (refuses an existing one unless `--force`) |
| `--to-stdout <path>` | single file to stdout (`restic dump`) |
| `--in-place` | restore over the original paths: requires `--force`; ArkHive first takes a **safety snapshot** of the paths it will overwrite (tag `pre-restore`) and prints its id, so the restore itself can be undone |
| `--owner preserve\|current` | default `preserve` when running as root, `current` otherwise (with a warning that ownership is not restored) |
| `--yes` | answers the final confirmation |
| `--json` | machine-readable result |

A missing required flag = exit 2 naming the flag, never a prompt.

### 10.3 Browse and find

- `arkhive ls [snapshot] [path]`: directory listing of a snapshot (size, mtime, mode).
- `arkhive find <pattern> [--host]`: which snapshots contain a path and its versions (date, size), to answer "when did this file last look right?".
- `arkhive mount <dir>`: read-only FUSE mount (`restic mount`) only if FUSE is available; otherwise a clear message pointing to `ls`/`restore --include`.

### 10.4 Bare-metal recovery

On a fresh host with no ArkHive config: `arkhive restore --repo <repository> --password-file <file> [--sftp-command <cmd>]` works without any config file. `doctor` prints exactly what is missing (restic binary, SSH key, password file) with distro-specific install hints (§12). The README has a one-page "my server is gone" procedure tested in CI (§13).

### 10.5 Restore drills

`arkhive drill [--sample N] [--db]` (default N = 50): restores N random files from the latest snapshot into a private temp dir, verifies them against the repository, optionally restores and test-imports one dump into a throw-away database name, removes everything, and reports pass/fail (exit 0/1, `--json`). Meant for a monthly timer, so restores are proven, not assumed.

### 10.6 `doctor`

Checks and explains, in this order: PHP version and extensions, distro and package hints, restic binary and version, config file found (and which), removed 1.x keys, password file permissions, repository reachability and lock, latest snapshot age, free space for dumps, clock skew, execution context detected (§11). Exit 0 if all green, 1 otherwise; `--json`.

## 11. Execution context: interactive vs unattended

ArkHive decides once, at startup, how it is running, and every command behaves accordingly.

| Signal | Meaning |
|---|---|
| `--no-interaction` / `-n`, env `ARKHIVE_NONINTERACTIVE=1` | forced unattended |
| `--interactive` | forced interactive (refused if stdin is not a TTY) |
| stdin and stdout are TTYs (`stream_isatty`, `posix_isatty`) and `TERM` is not `dumb` | interactive |
| no TTY | unattended (cron, scripts, pipes, CI) |
| `INVOCATION_ID` or `JOURNAL_STREAM` set | running under systemd: unattended, journald output mode |
| `CI` set | unattended |

| Behaviour | Interactive | Unattended |
|---|---|---|
| Prompts / wizard | yes | never: missing input = exit 2 naming the flag |
| Colours, emoji, progress bars | yes (respect `NO_COLOR`) | never |
| Log line format | human | one line per event, `YYYY-mm-ddTHH:MM:SS±zz level message`; under systemd no timestamp (journald adds it) and syslog priority prefixes (`<3>`, `<4>`, `<6>`); `--log-format json` available everywhere |
| Destructive confirmations | typed confirmation | only with `--yes` / `--force` as documented per command |
| Notifications | as configured | as configured |
| `--log-file <path>` | optional | optional, appended, rotated by size |

Scheduling helpers: `contrib/systemd/` (`arkhive-backup.service` + `.timer`, `arkhive-maintain.*`, `arkhive-drill.*` with `Nice=`, `IOSchedulingClass=idle`, `TimeoutStartSec=`) and `contrib/cron/` examples; `arkhive schedule --systemd|--cron` prints (never installs silently) the units/lines for the current config.

## 12. Linux portability

Supported and tested: Debian 12/13, Ubuntu 22.04/24.04, RHEL-compatible 9 (Rocky/Alma, PHP from AppStream module or Remi), Fedora (current), Alpine 3.20+ (musl, BusyBox), Arch. amd64 and arm64.

PHP >= 8.3 (§7): Debian 12 (8.2) and Ubuntu 22.04 (8.1) do not ship it, so on those PHP comes from packages.sury.org / `ppa:ondrej/php`; `doctor` and the startup check name that source in their hint.

- Prefer PHP over shell utilities: hashing (`hash_file`), free space (`disk_free_space`), file walking, permissions, temp dirs (`sys_get_temp_dir` honouring `TMPDIR`). Shell tools are used only when unavoidable (restic, dump binaries, ssh) and invoked by absolute path found by scanning `PATH` in PHP (no `command -v` through a shell).
- No GNU-only flags anywhere (BusyBox `stat`, `df`, `du`, `sha256sum`, `tar` differ); child processes run with `LC_ALL=C` so parsed output is locale-independent.
- Distro detection from `/etc/os-release` (`ID`, `ID_LIKE`); missing dependencies reported with the right command: `apt install`, `dnf install`, `apk add`, `pacman -S`, `zypper install`, including PHP extension package names per distro.
- MariaDB vs MySQL dump binaries (`mariadb-dump`, `mysqldump`), PostgreSQL client versions newer or equal to the server (warn otherwise).
- Config search adds `$XDG_CONFIG_HOME/arkhive/config`; `/etc/arkhive/config` stays the system location.
- Locks in `$XDG_RUNTIME_DIR` when set, else the temp dir; lock files carry PID and start time, and a stale lock (dead PID) is reported, not silently stolen.
- SELinux/AppArmor: restore preserves file contexts only where restic does; `doctor` warns when SELinux is enforcing and the target is outside the original paths.
- PHAR runs with `php` from `PATH`; `#!/usr/bin/env php` shebang; required extensions checked at startup with per-distro hints (`phar`, `json`, `mbstring`, `posix`, `pcntl` for signal handling, `curl` or `openssl` for `self-update`).
- Signals: SIGINT/SIGTERM during backup or restore stop restic cleanly, remove temp files and dump staging, release the lock, exit 130/143.

## 13. Testing in isolation

Everything runs on a development machine or in CI with no external host.

### 13.1 Unit (PHPUnit)

- exclusion conversion table (§5);
- config validation: missing keys; every removed key of §3 rejected with the migration message; boolean typing only on boolean keys; password file permission refusal;
- restic JSON summary and status parsing (fixtures captured from real restic output);
- self-update: release JSON parsing, semantic comparison, pre-release filtering, major-version guard, checksum mismatch refusal (HTTP layer mocked);
- execution-context detection: every signal and combination of §11 (TTY, `TERM=dumb`, `-n`, `ARKHIVE_NONINTERACTIVE`, `INVOCATION_ID`, `JOURNAL_STREAM`, `CI`, `NO_COLOR`) mapped to the expected mode and output format;
- distro detection and install hints from fixture `os-release` files of every distro in §12;
- restore planning: default target naming, non-empty target refusal, space check arithmetic, `--owner` defaults by uid, flag validation in unattended mode;
- config parser fuzzing (quoting, comments, empty values, unicode, CRLF) and exclusion conversion property tests (a converted pattern excludes exactly what the 1.x matcher excluded on a generated tree).

### 13.2 End-to-end (`tests/e2e/run.sh`, Docker)

`tests/e2e/docker-compose.yml`:

| Service | Image | Role |
|---|---|---|
| `sftp` | `atmoz/sftp` | stands in for the Storage Box: SFTP-only user, key authentication, published on a non-standard port to exercise `RESTIC_SFTP_COMMAND` |
| `mariadb` | `mariadb:11` | MySQL source, seeded schema, two databases |
| `postgres` | `postgres:16` | PostgreSQL source, seeded schema, two databases, password auth |
| `releases` | static HTTP server (e.g. `python:3-alpine` + `http.server`) | fake GitHub Releases API + assets for the self-update e2e, selected only in tests through an override of the API base URL (`ARKHIVE_RELEASES_API`, undocumented) |

The script, with a generated throw-away SSH key and repository password:

1. builds a fixture tree (random binary and text files, nested directories, files matching every exclusion pattern, a file with spaces, a symlink);
2. `arkhive init` then `arkhive backup` to the SFTP repository; asserts exit 0 and one snapshot;
3. asserts excluded files are absent from `restic ls latest`;
4. modifies 1% of the files, backs up again, asserts `data_added` is a small fraction of the first run;
5. `arkhive restore --snapshot latest --to <tmp>`; sha256 of every restored file equals the source;
6. imports every restored dump into a fresh database; row counts and a checksum query match;
7. back-dated snapshots (`restic backup --time`) + `arkhive maintain`; the kept set matches 7/4/6;
8. two parallel `arkhive backup`: the second fails on the lock;
9. world-readable password file: preflight refuses;
10. a 1.x config: preflight exit 2 listing every removed key;
11. `ps` sampling during the dumps: no password visible;
12. `decrypt-legacy` on an archive produced with the 1.x command line round-trips byte-identical;
13. self-update against the fake releases server: update, `--check`, checksum mismatch refused, major guard, `--rollback`;
14. restore matrix (§13.5);
15. teardown.

restic for tests: official static linux/amd64 release, pinned version, verified against the release `SHA256SUMS`.

### 13.3 Distribution matrix

The **built PHAR** (not the source tree) runs in containers of every distro in §12 (amd64; arm64 via QEMU on the release workflow): `doctor`, backup to a local repository, restore, `drill`, unattended-mode output check, missing-dependency messages (run once without restic and assert the distro-specific install hint).

### 13.5 Restore matrix (e2e)

Each case asserts exit code, output, and the restored bytes (sha256), mtimes, modes and, as root, ownership:

| Case | Expected |
|---|---|
| full restore to a new dir | identical tree |
| `--include` of a folder and of a single file | only those, identical |
| `--to-stdout` of one file | identical bytes |
| `--db <name> --import-as <new>` (MariaDB, PostgreSQL) | new DB with matching row counts and checksum; existing DB untouched |
| `--in-place --force` | safety snapshot created first and listed; data restored; a second restore from the safety snapshot brings the pre-restore state back |
| non-empty target without `--force` | exit 4, nothing written |
| insufficient space (small tmpfs target) | exit 4, both numbers printed, nothing written |
| non-root restore of root-owned data | succeeds with `--owner current` warning |
| bare-metal: no config, `--repo` + `--password-file` | succeeds |
| wrong password, unreachable repository, stale lock | exit 1 with the specific explanation, no partial target |
| interrupted restore (SIGTERM) | temp files removed, lock released, exit 143 |
| special files: symlinks, hardlinks, sparse file, empty dirs, names with spaces/unicode/newline, deep paths, files > 4 GiB (sparse) | preserved |
| wizard under pseudo-TTY: defaults only (Enter × N) | restores latest to the default new directory |
| unattended without `--snapshot` / `--target` | exit 2 naming the missing flag, no prompt |
| `drill` | pass on a healthy repository; fail after corrupting one pack file in the repository |

### 13.6 Fault injection (e2e)

SFTP server paused mid-backup and mid-restore (`docker pause`), repository disk full, corrupted pack file (`maintain` must report it), clock jump, dump server down: each case ends with a precise error, no partial snapshot counted as success, no leftover temp data, lock released.
